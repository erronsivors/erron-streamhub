# Crossember — техническое задание (v0.2, 09.11.2026)

Мульти-хаб стримера **Crossember** («made by erron for friends»). На ПК с OBS открыты только **OBS + Crossember**; всё остальное (чат, донаты,
алерты, оверлеи, статистика) — внутри хаба. Для себя и друзей, без продажи и без чужих серверов. Ничего не привязано к одному стримеру.

---

## 1. Что узнали из примеров

### Dangar StreamHub (концепт, скриншоты)
Хорошая структура разделов: Главная (зрители по площадкам, статус OBS, чат, последние события, быстрые действия) →
Мультичат (общая лента, клик по сообщению = вывести в OBS, статистика эфира) → Алерты и оверлеи (список типов,
предпросмотр, URL для OBS, тест сумм) → Подключения (карточки площадок со статусом) → Настройки.
Верхняя строка: «В эфире», таймер эфира, игра, профиль, разрешение/FPS.

### Stream Tools by b1trat3 v2.3.8 (установлен, изучен без запуска кода внутри)
- Python 3.14 + PySide6/Qt WebEngine, собран Nuitka; ~1,1 ГБ с Silero (torch 514 МБ). Хэш установщика совпал с сайтом.
- Локальный API только на `127.0.0.1:18765`, неизвестные маршруты → 404. Автозапуска, служб, правил брандмауэра нет.
- Данные: `%APPDATA%\b1trat3\...` (settings.json + несколько SQLite), логи `%LOCALAPPDATA%\b1trat3\...\Logs`
  (путь пользователя маскирует). Токены — Credential Manager / DPAPI.
- В комплекте лежит `client_config/.env.donatex_secrets` — по факту публичный OAuth client_id (PKCE), не утечка.
- В логе «crash» — это не падение, а дамп faulthandler от ошибки COM в потоке TTS; приложение продолжило работу.
- **Вывод:** сделано аккуратнее, чем казалось. Реальные минусы — закрытый код; refresh-токены YouTube/VK/Kick/GoodGame/DA
  проходят через сервер автора (OAuth-брокер); привязка к аккаунту сайта, онлайн-проверка подписки, лимит 2 ПК;
  сервер хранит IP и хэш ПК; есть глобальный хук клавиатуры/мыши, эмулятор ввода и Execute Code.

### Что берём из b1trat3 (идеи, не код и не дизайн)
- Единая лента событий всех платформ; тестовые события, не попадающие в статистику.
- Редактор «слева настройки — справа живой предпросмотр с тестовым режимом».
- Конструктор алертов как мини-видеоредактор: холст + слои + таймлайн (медиа / текст / звук / озвучка / действия OBS),
  переменные-чипы (Ник, Сумма, Сообщение), триггеры с условиями по сумме и источнику, «Тест», «Есть изменения».
- Один оверлей = один браузерный источник OBS, внутри — очередь любых алертов.
- Док для OBS (чат и события прямо в OBS), LAN-доступ к оверлеям по ключу.
- Профили экспорт/импорт без секретов, с откатом; автоматизации с кулдаунами и режимом «проверить без выполнения».
- Колесо, аукцион, список розыгрыша, таймер/subathon, сбор средств, счётчик смертей, soundpad.

### Что делаем лучше
- Никаких посредников: свои OAuth-приложения на площадках, токены не покидают ПК.
- Крупный читаемый интерфейс, без простыней свёрнутых секций; настройки — отдельная страница, а не модалка.
- Оверлеи — живые URL с обновлением по WebSocket, а не перегенерация HTML-файлов.
- Лёгкая озвучка по умолчанию (голоса Windows), тяжёлая (Silero / свой голос через Chatterbox) — опционально.
- Экран диагностики: какая площадка отвалилась, когда, почему, кнопка «переподключить».

## 2. Архитектура

| Часть | Выбор | Почему |
|---|---|---|
| Оболочка | Electron (последний стабильный) + TypeScript | Лучшие готовые библиотеки для Twitch/YouTube/OBS на JS; одно окно + встроенный сервер |
| Интерфейс | React + Vite, стиль ERRON (`F:\ErronAI\Дизайн\07 Twitch\brand.css`) | Палитра ночь/огонь/смесь/путь/свет, Unbounded + Manrope |
| Ядро | Node-процесс: шина событий, коннекторы площадок, очередь алертов | Всё в main-процессе, UI общается через IPC |
| Локальный сервер | Fastify + WebSocket, **только 127.0.0.1** (LAN — отдельный переключатель) | Отдаёт оверлеи и пульт для второго ПК |
| Хранилище | SQLite (better-sqlite3): настройки, события, статистика | Один файл, бэкап простой |
| Секреты | Electron `safeStorage` (Windows DPAPI, привязка к пользователю) | Токены не лежат открытым текстом |
| Оверлеи | HTML-страницы `http://127.0.0.1:<порт>/o/<id>?k=<ключ>` | Один URL на оверлей, живые обновления |

### Безопасность (обязательно с первого дня)
- Electron: `contextIsolation`, `sandbox`, `nodeIntegration: false`, строгий CSP, запрет навигации и новых окон, только
  нужные методы через preload.
- Сервер слушает только loopback; у каждого оверлея и у пульта свой случайный ключ (перевыпуск одной кнопкой);
  проверка `Origin`/`Host` против DNS-rebinding; LAN выключен по умолчанию.
- OAuth: PKCE / device-code где возможно; минимальные права; права на отправку сообщений — отдельным переключателем.
- Текст из чата и донатов на оверлеях выводится только как текст (никакого HTML) — защита от XSS через ник/сообщение.
- Ссылки из чата не открываются автоматически; нет выполнения кода из чата, нет эмуляции ввода (если понадобится — позже,
  с явными белыми списками).
- Никакой телеметрии. Логи маскируют токены, IP, пути пользователя. Секреты не попадают в экспорт и в Git.
- Зависимости — фиксированные версии, `npm audit` перед сборкой.

## 4. Разделы приложения

1. **Главная** — эфир (статус, время, игра), зрители по площадкам + график, статус OBS, мини-чат, последние события, быстрые действия.
2. **Мультичат** — общая лента со смайлами (7TV/BTTV/FFZ) и бейджами; клик = закрепить и вывести в OBS; ответ в нужную площадку; фильтры; пауза; на отдельный монитор / док OBS.
3. **События** — единая лента (донаты, сабы, рейды, фолловы…), повтор алерта, пометка «прочитано», тестовые события.
4. **Алерты** — оверлеи и очередь (пауза, пропуск, «стоп всё»), шаблоны в стиле ERRON, звуки, условия по сумме; позже — конструктор с таймлайном.
5. **Оверлеи** — вертикальный и горизонтальный чат, закреплённое сообщение, топ донатеров, последние сабы/донаты, активные болтуны, цели/сбор средств.
6. **Подключения** — карточки площадок, статус, переподключение, журнал ошибок (диагностика).
7. **Настройки** — порты, LAN и ключи, OBS, озвучка, профили, бэкап.

## 6. Два ПК
- **Стрим-ПК:** OBS + StreamHub (ядро, коннекторы, оверлеи на `127.0.0.1`). Оверлеи OBS берёт локально — сеть не нужна.
- **Игровой ПК:** пульт в браузере по LAN (`http://<стрим-ПК>:<порт>/remote?k=<ключ>`): чат, события, очередь алертов,
  закреп сообщения. LAN-сервер включается переключателем, слушает только адрес локальной сети, доступ по ключу пульта
  (перевыпуск одной кнопкой), правило брандмауэра Windows — только для частной сети.
- Позже: тот же пульт с телефона, Stream Deck.

## 7. Пользователи и стили (решение 09.11.2026)
- Хабом будут пользоваться и **друзья** — каждый на своём ПК со своими аккаунтами; данные и токены у каждого свои, локально.
- **Темы оверлеев (и алертов):** при создании выбирается стиль — «Общий» (нейтральный, без бренда ERRON) или
  «У костра» (фирменный ERRON). Тема = набор токенов (цвета, шрифты, скругления, анимации) + шаблоны; позже — свои темы.
- Интерфейс самого приложения — нейтральное название и логотип по умолчанию, тема «У костра» включается в настройках.
- Подключение площадок для друзей должно быть «в один клик»: публичные OAuth-клиенты без секрета (Twitch device-code,
  PKCE), где площадка требует секрет — у каждого своё приложение или временно ручной токен. Без общего сервера.
- Раздача: установщик + проверка SHA-256; подпись кода — позже (обсудить). Обновления — только вручную, без автозагрузки.

## 8. Идеи из 5 доп. видео b1trat3 (раскадровка 09.11.2026)
- **Единая модель правил «событие + площадка + фильтр → действие»** — одна для алертов, аукциона, интерактива, саундпада.
  Каждое правило со своим включателем, кулдауном и журналом.
- **Аукцион:** таймер (старт/пауза/±1 мин/продление при ставке), лоты с суммой и долей, правила ставок (донат/баллы,
  название лота из сообщения), очередь **«Требует решения»** (ставка без лота → назначить/создать), история, итог колесом
  (обычное / на выбывание). Победитель определяется до анимации.
- **Мультичат-оверлей:** вид «карточки»/«таблетки», цвет и включатель для каждого типа события, тестовый режим, статусы площадок.
- **Интерактив (управление игрой из чата)** — только позже и только с защитой: белый список окон-игр, запрещённые клавиши
  (Win, Alt+F4, Ctrl+Alt+Del…), лимит частоты, роли, большая кнопка «Стоп всем правилам», журнал. Предупреждение об античитах.
- **Аналитика (позже):** зрители по площадкам, ядро аудитории, топы, склейка аккаунтов одного зрителя — только локально.
- **Чего не хватает у b1trat3 и сделаем мы:** одна «панель оператора» на время эфира (чат + очередь алертов + аукцион +
  быстрые действия), фильтр/чёрный список ников и слов для оверлеев, ссылка-оверлей вместо ручных HTML-файлов.
- Оверлеи клавиатуры/геймпада, визуализатор, живые обои — низкий приоритет.

## 10. Универсальность (решения 09.11.2026)
- **Ничего не зашито под одного человека:** каналы, аккаунты, ключи, порты, темы — всё в настройках у каждого.
  В коде только публичные идентификаторы общих OAuth-приложений (без секретов).
- **Режим «1 ПК / 2 ПК»** — выбирается в мастере первого запуска, меняется в настройках.
  - 1 ПК: Crossember + OBS + игра на одном ПК; LAN-настройки скрыты.
  - 2 ПК: Crossember ставится на ПК с OBS; на игровом ПК чат и события открываются в браузере по ссылке с ключом (LAN).
- **Подсказки «!»** у каждой функции и настройки: что это, на каком ПК ставить, где и что нажать в OBS / на площадке.
  Текст зависит от выбранного режима (1 или 2 ПК).
- **Имя и бренд:** Crossember, знак-огонь, подпись «made by erron for friends». Темы оверлеев: «Общий» и «У костра».
- **Twitch:** одно общее публичное приложение (Client ID в коде, без секрета), вход по коду устройства;
  пишет аккаунт стримера, опционально — отдельный аккаунт-бот.
- **Долг по дизайну:** перед раздачей друзьям переработать оформление интерфейса — уйти от шаблонного «нейрослоп»-вида
  (эмодзи-иконки, однотипные карточки, градиенты), сделать свой узнаваемый стиль.
